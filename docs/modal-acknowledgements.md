# Одноразовые пользовательские окна

## Источники состояния

Согласие на cookie относится к браузеру и хранится локально в ключе `cookieConsent`.
Значения `accepted` и `declined` одинаково закрывают баннер при следующих загрузках. Только
`accepted` разрешает загрузку необязательной аналитики.

Остальные одноразовые окна относятся к аккаунту и синхронизируются с backend:

- ожидание верификации — `verificationNoticeAcknowledgedAt` текущего пользователя;
- предложение заполнить профиль — `profileFillPromptAcknowledgedAt` текущего пользователя;
- приветствие программы — `welcomeAcknowledgedAt` членства пользователя в программе.

Frontend не записывает эти состояния в `localStorage`. Загрузка страницы только читает
серверные признаки и не подтверждает показ автоматически. Timestamp появляется после явного
закрытия окна или нажатия его основной кнопки.

## Пользовательские правила

- Ожидание верификации показывается, пока аккаунт не верифицирован и уведомление не подтверждено.
- Предложение заполнить профиль показывается только владельцу неполного профиля.
- Приветствие показывается только участнику конкретной программы и только в её detail-разделе.
- Повторный вызов любого подтверждения безопасен и возвращает уже зафиксированное состояние.
- Подтверждения аккаунта работают одинаково на разных устройствах и не переносятся между
  пользователями; приветствие программы дополнительно изолировано по программе.

## Используемые API

- `POST /auth/users/current/acknowledge-verification-notice/`;
- `POST /auth/users/current/acknowledge-profile-fill-prompt/`;
- `POST /programs/<program_id>/acknowledge-welcome/`.

Дублирующее приветствие на главной странице офиса удалено. Единственный сценарий приветствия
остаётся на detail-странице программы.
