# Пустое состояние обложки проекта

База DEV: `2324f52345fe608991e888a514aefc491e578bcb` после merge #350.

Backend сразу назначает новому проекту стандартную обложку. Раньше общий UploadFile
воспринимал любой непустой URL как успешную загрузку пользователя и показывал
«Файл успешно загружен» / «Заменить файл».

Теперь стандартная обложка, определённая по canonical `isDefaultCover === true`,
показывает «Стандартная обложка» в центре и «Загрузить файл» снизу. То же оформление
используется при пустом control до выбора файла: оно не записывает фиктивный URL,
не создаёт DefaultProjectCover и не снимает required-валидацию.

После успешной пользовательской загрузки флаг переключается в false и действие
меняется на «Заменить файл». Компактная иконка сброса справа сверху удалена по
уточнённому требованию; нового действия сброса в другом месте не добавлено.
Существующие backend reset-cover и сервис команды не менялись.

Общий UploadFile получил необязательный нейтральный `presetLabel`: он меняет только
оформление предзаданного файла. По умолчанию параметр null, поэтому presentation
и другие места использования сохраняют прежние подписи и сценарий удаления.
Обложка по-прежнему запрещает File DELETE через `removable=false`.

клавиатуры и открытие выбора файла дополнительно проверены компонентным тестом.
