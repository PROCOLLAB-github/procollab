# Размеры изображений программы

Запрос: рядом с каждым элементом оформления показать, какой размер изображения нужен.
Локальная текстовая итерация существующего раздела «Основное → Изображения».

Ожидаемый результат: у каждого из трёх загрузчиков всегда видны рекомендуемые размеры
и правила отображения, включая пустое состояние. Кнопка связана с подсказкой через
`aria-describedby`. Существующие upload/save/remove, API и ограничения не меняются.

## Основания рекомендаций

- Обложка: **1800 × 320 px**, около 5,6:1. Это рекомендация для исходника примерно
  в 2× разрешении относительно существующей desktop-шапки (ширина до ~867 px,
  высота 155 px). `office.component.scss`: max-width 1040 и grid 2fr/10fr.
  `detail.component.scss`: `object-fit: cover`, центрирование, mobile height 136 px.
  Поэтому на телефоне края исходника обрезаются. Логотип перекрывает нижнюю часть.
- Логотип: **512 × 512 px**, квадрат 1:1 с отступами вокруг знака. Существующий
  AvatarComponent использует круг и `object-fit: cover`; программа отображает его
  размером 123 px на desktop, 105 px на mobile, 100/64 px в каталоге.
- Баннер регистрации: рекомендуемая ширина **1800 px**, высота по содержимому.
  `program/detail/main/main.component.scss`: `width: 100%`, без фиксированной высоты
  и crop. `main.component.html`: показ тем, кто ещё не участник/организатор/эксперт.

Это рекомендации по подготовке, а не новые обязательные размеры или upload validation.
Для баннера не вводится выдуманная фиксированная пропорция. Название «Обложка (шапка)»
уточняет расположение существующего поля, key `coverImageAddress` сохраняется.

## Проверки

- Checked by source: все три подсказки используют существующие image keys;
  validators, accept, upload/save/remove и API не менялись. Ограничения не добавлены.
- Checked by build: Angular development build PASS; scoped ESLint и Prettier PASS.
- Checked in browser: Chrome + настоящий локальный Django/PostgreSQL,
  1440×1000, 390×1000, 360×1000. Все три подсказки видны, aria-describedby связан
  с нужным текстом, горизонтального overflow и page errors нет. Фактическая шапка
  866.66×155 на desktop и 328×136 на mobile, object-fit cover.
- Checked visually: desktop/mobile screenshots просмотрены; размеры и пояснения
  сгруппированы под названием, доступны до выбора файла.
- Новые unit tests не добавляются для статических подсказок; обязательный suite запускает dev CI.
- Not checked: live organizer-сессия на dev отсутствует; реальная загрузка в Selectel
  не проверялась, upload flow в этой итерации не меняется.
