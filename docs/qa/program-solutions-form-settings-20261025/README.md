# QA01: настройка формы и неполные черновики

Проверены реальные организаторские настройки и сохранение неполного решения для КЧ, хакатона и неконкурсной программы. Исправлены ложное предупреждение о несохраненных изменениях в новой форме и подсказка о сдаче в неконкурсном редакторе. API, права, структура экранов и SCSS не менялись; полный первый выпуск еще не завершен.

Backend source `ad3945e` (runtime `30c0d3e`); frontend поверх `d2a2cd3f`, точные source hashes в manifest/build provenance; C00 `1.14.0`. Только новые синтетические программы 27/28/29, решения 42/43/44, prefix `qa01f-20261025-a8f2c339`. Настоящие Angular/Django/JWT/PostgreSQL 18, locmem mail; внешние запросы браузера блокировались. Credentials/JWT не включены в Git.

## Ошибка и исправление

У формы с template=null и fields=[] dirty сравнивал fallback шаблона для PUT с настоящим null сервера. Поэтому первое явное применение шаблона открывало «Есть несохраненные изменения» и оставляло поля пустыми до подтверждения потери несуществующих правок. [Исходный FAIL](before-finding.json) и screenshot сохранены; реальный baseline UI относится к КЧ27. Обе формы воспроизведены красной параметризованной регрессией: 2 failed/7 passed.

Теперь dirty сравнивает фактически выбранный template, включая null. Первый шаблон копируется без discard prompt и без автоматического PUT; повторная замена после реальной правки по-прежнему требует подтверждения. Request serializer и save guards сохранены. Профильные 9 tests PASS. У неконкурсного редактора подсказка больше не обещает будущую сдачу; существующий noncompetitive test усилен, отдельный финальный browser read подтвердил текст, отсутствие submit и сохраненные 0/false.

## Происхождение и границы

Initial seed committed три пустые программы/регистрации, затем упал при сборке manifest: Expert имеет PK без имени id. Подготовленные строки проверены и сохранены, не пересоздавались. Baseline снят после этого setup, до тестируемых API/UI writes; это явно не pre-seed SHA. [Recovery](setup-recovery.json) перечисляет исключенные новые setup rows. Все прежние выбранные строки 15 domain моделей с этого момента неизменны; новые решения/поля/ответы появились только в изолированных программах. Auth/session/last_activity не входят в утверждение.

Продуктовый baseline FAIL сохранен отдельно. Первый post-fix harness не нашел preview в app-modal, потому что содержимое вынесено в overlay; позже harness ожидал null вместо отсутствующего пустого ответа. Оба FAIL сохранены. После уже успешного save0/false КЧ выполнено только чтение/reload/tabs, без сброса и повторного PATCH; остальные программы прошли свои фазы. Результат объединяет явно отмеченные фазы, не заявляет один непрерывный green run. JavaScript exceptions в записанных browser checks=0.

Основной manager/captain путь хакатона выполнен при390, КЧ/неконкурсного — при1440. Сохраненные состояния проверены при320/390/768/1440 без горизонтального overflow. Часть screenshots просмотрена; они могут отражать внутреннюю вертикальную прокрутку. Mont/существующие controls сохранены, remote avatars блокировались. Полные a11y/zoom, invitation lifecycle, competitive submit, публичный/новый manager analytics UI, production CDN/рассылки и общий первый выпуск не заявляются.

[Build after](build-after.json) и [final](build-final.json) используют копии generated build с заменой origins ровно одного JS chunk. Source environments не патчились. [Manifest](local-artifacts.json) содержит SHA256 raw wire, FAIL reports, screenshots, helpers и финальных sources. Все три решения остаются drafts с одним капитаном, ровно двумя ответами0/false, без приглашений/сдачи/snapshot/публикации/оценок; creation flags=False.
