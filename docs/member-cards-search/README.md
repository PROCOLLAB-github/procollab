## Карточка

`MemberCardComponent` применяется только в каталоге `/office/members`.
Общий `InfoCardComponent`, карточки команды проекта, статистика и фильтры не переработаны.
Используются существующие данные `User.personal` и `User.relations`, полученные через
`MemberRepository` / `userFromRaw`; новых API-полей нет.

Имя и фамилия занимают две строки, специальность и возраст — отдельный блок.
Навыки выровнены слева и занимают максимум две строки. Ширины плашек измеряются
тем же шрифтом в невидимом слое; заранее резервируется место для `+N`.
При изменении данных, ширины или загрузке шрифта измерение обновляется.
Наблюдатель и подписка на шрифт освобождаются при уничтожении компонента.
Длинный навык обрезается многоточием; полный текст и скрытые навыки доступны в
`title`/семантике списка, а все данные — на странице профиля.

Карточка содержит одну ссылку на существующий профиль; CTA «Профиль» является
визуальной частью этой ссылки. Вложенных интерактивных элементов нет.

## Поиск: что воспроизвелось до изменений

24.09.2026 выполнены ограниченные read-only запросы к публичному endpoint,
который использует Angular: `/auth/public-users/?user_type=1&limit=1&fullname=…`.
Сохранены только коды ответа и количества: [live-search-before.json](live-search-before.json).

| Запрос                             | DEV, count | PROD, count |
| ---------------------------------- | ---------- | ----------- |
| Иван                               | 5          | 365         |
| иван                               | 0          | 10          |
| ИВАН                               | 0          | 0           |
| Иванов                             | 2          | 171         |
| иВаНоВ                             | 0          | 0           |
| Иван Иванов                        | 5          | 365         |
| иван иванов                        | 0          | 10          |
| Иван НесуществующаяФамилияПроверка | 5          | 365         |

Все ответы — HTTP 200. Проблема есть **и на DEV, и на PROD**.
Backend `UserFilter.fullname` в проверенных ветках dev/master одинаков:
слова соединялись через OR, поэтому полное имя возвращало совпадения только
по одному слову. Кириллический `icontains` на работающих окружениях фактически
регистрозависим. Точная настройка collation live-БД не запрашивалась.

Отдельная frontend-проблема: `throttleTime(300)` без trailing мог терять
последние символы быстрого ввода. Теперь только поле имени использует debounce,
обрезку крайних пробелов и объединение внутренних пробельных символов.
Resolver учитывает `fullname` из URL. Очистка поиска удаляет query-параметр;
пагинация получает актуальный total, поздняя страница старого поиска игнорируется.
Остальные фильтры сохраняют прежнюю обработку.

## Зависимость от backend и ограничения

Для исправления регистра и полного имени требуется сопутствующий backend PR
из `fix/dev-member-name-search`. URL, формат ответа и права доступа сохранены.
Никакой фильтрации всех пользователей в браузере нет.

На DEV/PROD страницы участников перенаправляют в login: безопасной
авторизованной сессии нет. Ввод поиска в live-браузере и live-проверка результата
после исправления не выполнены. Изменения не развёрнуты; доказательство
исправления — локальные Angular-тесты и тесты публичного API на PostgreSQL.

React, статистика, зависимости, workflows и схема БД не изменены.
Merge и deploy не выполнялись.
