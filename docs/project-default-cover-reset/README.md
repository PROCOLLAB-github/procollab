## Причина и поведение

Раньше корзина обложки вызывала глобальный `DELETE /files/`. Для стандартного файла другого владельца это закономерно даёт 403. После удаления собственного файла пустая обложка конфликтует с `Validators.required`. Удалять общий файл или делать обложку необязательной нельзя.

Сообщение о 403 на DEV получено от пользователя. Дополнительно проблема воспроизведена в локальном браузере на исходном Angular: `DELETE /files/?link=http://localhost:8012/cleanup-files/default.png` → 403, общий файл сохранён. Код исходного локального стенда имеет то же дерево Git, что Angular base выше. Удалений на живом DEV автор изменений не выполнял.

Теперь canonical Project detail передаёт `is_default_cover`, существующий camelcase interceptor преобразует его в `isDefaultCover`:

- `true`: действие удаления/сброса отсутствует, замена загрузкой доступна;
- `false`: доступно «Вернуть стандартную обложку»;
- поле ещё неизвестно: удаление и сброс недоступны, URL не используется для угадывания типа;
- успешный upload делает обложку пользовательской; замена custom A → custom B не требует предварительного DELETE.

Команда `POST /projects/{Project.id}/reset-cover/` возвращает `{cover_image_address, is_default_cover: true}`. Форма получает фактический URL из ответа, остаётся валидной; `Validators.required` сохранён. `Project.id` берётся из инициализированной формы, а не из ID связи с программой.

Backend проверяет те же права, что обычный Project PUT: лидер, действующие права collaborator/invite на черновик, опубликованный проект и временные ограничения программы. Manager/expert не получают новых прав. Уже стандартная обложка возвращается идемпотентно. Если стандартной обложки нет, ответ 409 с `code=default_cover_unavailable` сохраняет прежний URL и показывает безопасный русский текст.

Сначала backend фиксирует стандартную обложку, затем через `on_commit` допускает очистку собственного свободного UserFile. Чужой, системный, используемый другим проектом или отсутствующий файл не удаляется. Отказ CDN не отменяет reset и не превращает его в 500. Глобальные права DELETE не меняются. `is_default_cover` read-only; сериализатор кеширует набор стандартных URL на экземпляр, включая `many=True`, без N+1.

## Состояние редактора

`ProjectCoverResetService` живёт вместе со всем редактором. Смена шага не теряет ответ уже сохранённого сброса. Повторный клик блокируется; на время операции блокируются замена файла, обычное сохранение и сдача формы, чтобы они не записали прежний URL поверх reset. При смене проекта, повторной инициализации того же ID и уничтожении редактора подписка отменяется. Дополнительная проверка URL исключает применение ответа после параллельной замены файла.

Кеш detail инвалидируется до команды и при её завершении, ошибке или отмене: отмена клиентского HTTP не доказывает, что сервер не успел сохранить результат.

Общий `UploadFileComponent` получил только нейтральные `removable`, `replaceable`, `busy` с прежними значениями по умолчанию. Он не знает про Project или reset-cover. Presentation сохраняет DELETE, cleanup autosave, explicit empty value и offline queue из #349. Модели React, current_application, analytics-widget, зависимости, workflows, миграции и правила доступа не менялись.
