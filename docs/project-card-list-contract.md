# Неполный lifecycle в карточке «Моих проектов»

## Источник и безопасное поведение

`/auth/users/projects/` ранее возвращал `partner_program` только с `id/name`.
Отсутствующий `isSubmitted` ошибочно разрешал подпись «можно редактировать».
Backend расширяет компактный контракт до `id`, `name`, `program_link_id`,
`program_id`, `is_submitted`. Выбранная связь с минимальным PK совпадает с detail.

Карточка разрешает подпись о редактировании только когда пользователь — лидер
и либо связи нет, либо её `isSubmitted === false`. Связь без достоверного состояния
сдачи означает «только просмотр», в том числе для черновика.

Lifecycle остаётся независимым от роли: `submitted > draft > program > published`.
При неизвестном состоянии связи сохраняется нейтральный статус «В программе»
(или «Черновик» при `draft=true`). `canSubmit` не используется для определения сдачи.
Неизвестный пользователь не считается лидером.

CTA всегда «Открыть» и ведёт в `AppRoutes.projects.detail(id)`. Шаблон, стили,
размеры, аватар, подписки, списки all/subs, detail guard и редактор не изменены.
Это отображение данных; серверные права не меняются.

## Интеграционная регрессия

`info-card-list-contract.spec.ts` подаёт сокращённый snake_case JSON через
`HttpTestingController`, настоящий `CamelcaseInterceptor`, `ApiService`,
`ProjectHttpAdapter`, `ProjectRepository` и `GetMyProjectsUseCase` в `InfoCardComponent`.
Маппинг не подменяется готовой camelCase-фикстурой.

Проверяются true/false/отсутствие `is_submitted`, draft, смена лидера/участника/
неизвестного профиля и последовательные ответы с известным/неизвестным состоянием.
Для сданного проекта результат — «Сдан в программу / Лидер / только просмотр».
Существующая матрица карточек, List и Dashboard сохраняется.

## Будущая DEV-приёмка

Backend-контракт нужно развернуть перед Angular. На старом backend защита уже
убирает обещание редактирования, но определить факт сдачи без данных не может.
После отдельного разрешения на merge/deploy сравнить list/detail одного сданного
DEV-проекта: `program_link_id` и `is_submitted` должны совпасть; карточка и detail
должны одинаково показывать недоступность редактирования.

Эта live-проверка сейчас не выполнена: задача завершается двумя Draft PR без deploy.
