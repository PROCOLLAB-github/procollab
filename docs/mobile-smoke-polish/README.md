## Почему было два сообщения о соединении

`ConnectionStatusToastService` и `ChatRealtimeRepository` подписывались на один `WebsocketService.connectionLost$` и создавали два разных snackbar. После порога повторных попыток событие приходило снова, примерно каждые пять секунд, поэтому уведомления постоянно обновлялись.

Теперь UX принадлежит одному сервису. Статус WebSocket различает подключение, недоступность и завершённую сессию. При длительном сбое появляется текст: «Чат временно недоступен. Сообщения и статусы могут обновляться с задержкой. Подключаемся автоматически». Это не утверждение о недоступности HTTP API или интернета в целом.

Уведомление можно закрыть. Закрытое сообщение не появляется снова в течение того же сбоя. Если его не закрывать, оно исчезает при восстановлении WebSocket; следующий отдельный сбой создаёт новое сообщение. Повторные подключения продолжаются автоматически. Явное закрытие сессии отменяет ожидающий retry, а teardown освобождает обработчики и старый socket.

API, авторизация, правила доступа, payload сообщений, очередь исходящих сообщений и бизнес-процессы проектов/программ/приглашений не менялись. Изменены транспортный lifecycle и отображение его состояния.

## Воспроизведение visual regression

Нужны Chrome/Chromium, Playwright, Python с Pillow и NumPy. `PLAYWRIGHT_MODULE` и `CHROME_PATH` позволяют указать существующие runtime без изменения зависимостей проекта. Все API и WebSocket в harness заменены синтетическими fixtures; запросы на live API не отправляются.

Для воспроизводимой проверки установить `QA_BUILD_ROOT` в путь к нужной сборке: `before-dist` для обоих запусков `before`, `after-dist` для `after`, `connection` и `contacts`. Например, PowerShell: `$env:QA_BUILD_ROOT = '.desktop-regression/mobile-smoke/after-dist'`. Без этой переменной скрипты используют обычный локальный HTTP preview.

1. Собрать baseline из указанного выше commit в отдельном checkout и исправленную ветку одинаковой development-конфигурацией. Сохранить результаты как `before-dist` и `after-dist`.
2. В отдельных терминалах запустить preview:

```text
node docs/desktop-regression/serve.cjs .desktop-regression/mobile-smoke/before-dist 4451
node docs/desktop-regression/serve.cjs .desktop-regression/mobile-smoke/after-dist 4452
```

3. Снять основные и дополнительные состояния для обеих сборок:

```text
node docs/mobile-smoke-polish/visual.cjs before http://127.0.0.1:4451 320,390,768,1440,1920 .desktop-regression/mobile-smoke/screenshots
node docs/mobile-smoke-polish/visual.cjs after http://127.0.0.1:4452 320,390,768,1440,1920 .desktop-regression/mobile-smoke/screenshots
node docs/mobile-smoke-polish/visual.cjs before http://127.0.0.1:4451 320,390,768,1440,1920 .desktop-regression/mobile-smoke/screenshots details
node docs/mobile-smoke-polish/visual.cjs after http://127.0.0.1:4452 320,390,768,1440,1920 .desktop-regression/mobile-smoke/screenshots details
python docs/mobile-smoke-polish/compare.py .desktop-regression/mobile-smoke/screenshots/before .desktop-regression/mobile-smoke/screenshots/after docs/mobile-smoke-polish/desktop-comparison.json
node docs/mobile-smoke-polish/connection.cjs http://127.0.0.1:4452
node docs/mobile-smoke-polish/visual.cjs contacts http://127.0.0.1:4452 390
```

В PowerShell аргумент со списком ширин следует заключить в кавычки. Ширины можно запускать по отдельности в тот же каталог: PNG имеют уникальные имена, comparator проверяет все 44 обязательные desktop-пары и падает при отсутствии любой из них. Harness сбрасывает прокрутку окна и внутренних scroll-контейнеров перед основным скриншотом; дополнительные состояния прокручиваются явно. После генерации JSON отформатировать Prettier перед commit. Полные build/PNG-артефакты остаются в приватном `.desktop-regression`, в Git включены representative screenshots и результаты сравнения.

## Review и ограничения

Source review: desktop media boundary, отсутствие изменений API/permission/domain-правил, сохранность очереди сообщений, отмена retry при закрытии, lifecycle подписок, доступность close-кнопки и сохранение focus на контейнере поиска — проверены. Существенных незакрытых замечаний в этом diff нет.

Браузерные проверки выполнены в headless Chrome на Windows с fixtures. **Реальные iOS/Android, Safari/WebKit, загрузка файлов, live API и реальный сетевой обрыв на dev-стенде не проверены.** После merge требуется повторный smoke-test на устройствах по десяти пунктам выше, включая уход приложения в фон и восстановление чата. Изменения данных и backend migration не требуются.
