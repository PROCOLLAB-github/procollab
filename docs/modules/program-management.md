# Управление программой · V1

Дизайн утверждён пользователем 17.10.2026 («В целом да»).
[Figma V1](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=201-5390).

Организатору доступны два входа вокруг аватара программы: «Оценка проектов» и «Управление программой». Последний открывает участников. Старые отдельные кнопки участников и проектов у организатора убраны. Эксперт без роли организатора сохраняет прежний маршрут оценивания.

## Границы

- Участники: таблица ФИО, почты, города и даты регистрации именно в программе; только чтение, поиск по имени/почте, серверная пагинация.
- Проекты: сдача и оценивание раздельно, кейс, руководитель и прямая ссылка на презентацию. Выбор одной строки открывает одну панель с просмотром команды и переходом к оценке.
- Команда: состав и роли; desktop side panel, mobile full screen. Закрытие возвращает фокус; возврат из оценки восстанавливает выбор и query списка.
- Оценивание: чтение оценок выбранного проекта. Существующий эксперт дополнительно получает переход в прежнюю форму с точным `project_id`. Роль организатора сама по себе не даёт право выставлять оценки. Несданное решение и неконкурсная программа блокируют переход из списка.
- Аналитика: существующий компонент и API, без изменения определений показателей.
- Настройки: Основное, Сроки, Материалы. Явное сохранение, предупреждение об уходе, сохранение введённых значений при ошибке, optimistic concurrency. Даты явно в Москве UTC+3. Повторное открытие истёкшего срока требует подтверждения сервера.
- Материалы: файл через существующий FileService либо URL; изменение и удаление записи программы сохраняют исходный UserFile.

Индивидуальные действия с участниками, массовые операции, исключение проектов, возврат на доработку и смена кейса отложены.

## Интеграция

Новый приватный port/use case/repository/HTTP adapter использует `/programs/:id/management/`. CamelcaseInterceptor сохраняет существующее преобразование JSON. Почта и прочие приватные данные не попадают в общий EntityCache. После записи событие ProgramUpdated очищает кеш страницы и списка программ, включая persistent cache; старый ответ списка не заменяет новые данные.

Backend проверяет manager именно этой программы либо существующий staff/superuser scope. Прямые чужие ID и эксперт без manager не получают доступ. Полный контракт находится в backend `docs/modules/program-management.md`. Backend PR должен попасть в dev раньше UI.

Native adapters Button/Field/Choice/Table, существующие Modal/Icon/Pagination/Alert и Mont сохраняют PROCOLLAB DS. Foundation подключена локально также на desktop; глобальные компоненты не менялись.
