Открыть [интерактивный макет](http://127.0.0.1:8769/manager-v1/?screen=solutions). Четыре раздела сохранены. «Команда» остается второй вкладкой внутри заявки. Все имена и записи в прототипе вымышлены; действия меняют только память этой вкладки. Перезагрузка, смена формата или состояния сбрасывает демонстрационные действия. Прототип не вызывает API, не отправляет письма, не создает Excel и не проверяет серверные подписи. Панель «Ответ на действие» относится только к просмотру макета.

## Что добавлено

- «Активные» / «Архив» в существующем разделе решений. Архив дает чтение материалов, принятого состава и истории; оценки сохраняются, но отдельного просмотра архивных значений текущий reader не предоставляет. Восстановление не предлагается: соответствующего API нет.
- Смена кейса черновика или сданной работы: выбор актуального кейса → последствия → подтверждение. Сохраняются материалы, команда и оценки; снимаются только подходящие под правило API назначения без оценок.
- Исключение принятого участника: прежний и новый состав доступны в истории. Капитан не исключается этой командой; удаление его регистрации архивирует решение. Регистрация самого исключенного участника остается.
- Снятие с участия / архив неконкурсных материалов: сохраняются материалы, состав и оценки; снимаются назначения и ожидающие приглашения. После успеха работа исчезает из активного списка.
- Участники программы → выбор регистраций → конкретные последствия → подтверждение → независимая история удаления. Выбор капитана, принятого участника, ожидающего приглашенного и человека без решения различается. Учетная запись и другие программы сохраняются. Удаление регистрации уже архивного участника не переписывает архивный состав или прежние события.
- Конфликт связи с Project блокирует всю новую команду; частичного удаления нет. Старые Project-программы продолжают прежний путь. Прототип показывает это состояние, а не доказывает сохранность production данных.
- Первая сдача организатором: неполный черновик блокируется с названиями полей, готовый — подтверждается. Повторная сдача и искусственная сдача неконкурсной работы не предлагаются. Состояние «Готовый черновик» показывает успешный путь на работе «Лаборатория практики».
- История решения открывает «До изменения» / «После изменения», сохраняя материалы, 0, «Нет» и состав. Общая история регистраций доступна и без связанного решения. Это отдельные просмотры, не третья вкладка команды.

В реальном UI все числа и эффекты берутся из ответа сервера, не вычисляются из демонстрационных назначений. На мобильном списки перестраиваются с подписями, definition list последствий идет одной колонкой, dialog прокручивается; история не расширяет набор вкладок заявки.

Bounded critique (не полный `$impeccable critique`):

1. Отсутствовали административные действия, уже существующие в API: добавлены конкретные entry points, previews и конечные состояния.
2. Снятие можно было принять за удаление данных: прямо указаны сохранение материалов/состава/оценок, отзыв pending и снятие assignments; архив остается читаемым.
3. Удаление регистрации без решения теряло место в истории: добавлена отдельная история программы, без дублирования анкеты и email.
4. После изменения данных или неопределенного результата опасен повтор старого подтверждения: apply блокируется, требуется новый просмотр. Busy предотвращает повторный клик и закрытие до результата.
5. Pending и принятый состав легко смешать: отдельный блок приглашений, счетчики состава и отображение отозванной связи уточнены; смена формата сбрасывает демонстрационные данные.

Polish сохраняет Mont, цвета и существующие кнопки/модальные окна. Полный accessibility audit и WCAG AA не заявляются. Клавиатура/видимый фокус/области действий, длинные тексты и 320/390/768/1440 проверяются в browser evidence. Контраст inherited controls не модернизировался глобально.

## Current и target behavior

Сейчас организаторский путь использует Project DTO, списки проектов, проектные назначения и жесткий фильтр наличия презентации. При выборе ProgramSolution нужны настоящие решения, их принятый состав и снимок сдачи. Поля формы зависят от программы, поэтому презентация не может быть универсальным фильтром.

Сохраняются четыре текущих раздела: «Решения», «Оценивание», «Результаты», «Аналитика». Список или кейс открывает материалы в модальном окне; «Команда» — вторая вкладка той же заявки. Из назначения можно открыть оценку и вернуться в исходный список с прежними фильтрами. Никакого выбора самостоятельной команды и подмены Solution.id на Project.id нет.

Роль этого пути — организатор/администратор с действующим server-side доступом. Кнопки не являются проверкой прав. Экспертный путь D01, участник и публикация для внешних посетителей здесь не перепроектируются.

## Design QA и Impeccable

Operate constraints: сканируемость существующих списков, знакомые действия, одна модальная поверхность с возвратом, отсутствие декоративного редизайна. Layout review: прежняя сетка, порядок чтения и плотность; мобильные таблицы перестраиваются в подписанные строки, длинные названия переносятся.

Bounded critique и polish:

1. Жесткий фильтр «Презентация» не охватывает хакатон: заменен выбором настроенного поля и наличия ответа.
2. 0/False можно ошибочно прочитать как отсутствие: демонстрационные данные и проверки явно сохраняют заполненность и значения.
3. Подпись «Команда» скрывала смысл среднего: переименована в «Участников / решение», текущая формула сохранена.
4. Плотная таблица на мобильном теряла контекст колонок: сохранено преобразование в строки с подписями, проверены длинные названия.
5. Добавленное обязательное поле создавало неоднозначность старых сдач: показаны «Неприменимо» и объяснение снимка формы.

Механический Impeccable layout scan вернул `[]` с exit 0. Он анализировал только статический HTML shell; динамические элементы проверялись браузером. Полный `$impeccable critique` не запускался.
