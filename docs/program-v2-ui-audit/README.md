# Аудит управления программами V1/V2

Задача: восстановить согласованный визуальный язык PROCOLLAB, сохранив отдельные модели Project и Solution, существующие HTTP-контракты, права, URL, фильтры и проверки конфликтов.

Исходная версия Angular: `9ef90b58`, чистая рабочая копия. Ветка: `fix/program-v2-design-system`. Backend и React не изменяются. Merge, deploy и миграции не выполняются.

## Источники и границы проверки

Figma MCP доступен через подключение PROCOLLAB PRO. Исследованы страницы UI KIT, 10–14, 17–24, 27 и «Аналитика»: [полная карта фреймов](figma-inventory.json). Прочитаны контракты foundations, components, patterns, templates, legacy и decisions UI Kit. В файле остаются пометки Proposed и TEMP Inter; они не означают разрешения на замену действующего Mont, навигации или бизнес-логики.

Визуальные источники: [UI Kit](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=0-1), [управление](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=179-3219), [эксперты](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=452-3220), [распределение](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=452-3221), [результаты](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=526-3628), [аналитика](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE?node-id=753-3219). Для восстановления конкретного поведения панели «Фильтры», чекбоксов и действий используется действующий V1 согласно заданию: ранний фрейм экспертов содержит более старую панель с select и пятью верхними вкладками.

Скриншоты в задании фактически не переданы. Снимки «до» сняты с исходного Angular-кода. Браузер запускает настоящее приложение на localhost; ответы API заменены изолированными fixtures, включая действующие C00-сценарии Solution. Это проверка UI и запросов клиента, а не приемка реального сервера или действующих программ. Ни один запрос браузерного стенда не отправляется во внешний API.

## Карта маршрутов и сущностей

Корень: `/office/program/:programId/management/:section`, определен в [detail.routes.ts](../../projects/social_platform/src/app/ui/routes/program/detail.routes.ts). `solutionStorageMode` выбирает ветку; параметр `section` и вложенный `?tab=` общие.

- `participants`: общий список регистраций, ответы анкеты, выбор, выгрузка, удаление с разными V1/V2-предпросмотрами.
- `projects`: V1 — связи ProgramProject/Project; V2 — заявки с `application.solutionId`, решения, принятый состав команды, архив, история административных действий.
- `experts`: общий roster приглашений и областей кейсов; назначения V1 по Project, V2 по Solution. Вложенная вкладка распределения и диалоги не являются отдельными route.
- `results`: общий компонент рейтинга; V2 адаптер сохраняет `SolutionRef` и не добавляет Project FK.
- `analytics`: разные источники Project/Solution, общая композиция; вложенные списки, оценки, фильтры, напоминания, XLSX.
- `settings?tab=basic|dates|materials|project-form|criteria|organizers|registration`: семь подразделов. `project-form` в V2 открывает форму решения; остальные редакторы общие.
- `certificates`: общий редактор шаблона, выдача/письмо, журнал, подтверждения, выбор получателей, PDF/архив.
- `projects/:linkId/evaluation`: существующий V1 просмотр оценок. Дополнительные маршруты решений `/solutions/:solutionId`, редактирование и `/evaluation`; создание/подготовка `/launch` и публичные опубликованные решения связаны с управлением, но их бизнес-потоки не переписываются.

Контракты сверены по [ProgramManagementHttpAdapter](../../projects/social_platform/src/app/infrastructure/adapters/program/program-management-http.adapter.ts), [EvaluationHttpAdapter](../../projects/social_platform/src/app/infrastructure/adapters/program/evaluation-http.adapter.ts), [SolutionHttpAdapter](../../projects/social_platform/src/app/infrastructure/adapters/solution/solution-http.adapter.ts) и domain-моделям. Счетчики roster Project не используются как счетчики назначений Solution.

## План до реализации

1. Выделить представление таблицы roster из V1 в общий компонент (строки, avatar, status, profile, checkbox, menu, mobile, footer). Оставить API, статус программы, отбор строк, protected checks и операции в существующих родителях. Проверить исходные V1 tests и оба экрана в браузере.
2. Перевести V2 экспертов на V1 toolbar/filter Modal, общий roster и bulk-панель. Удалить подключение SCSS аналитики; состояния и диалоги использовать из экспертов. Счетчики остаются вычисленными по SolutionAssignment.
3. Восстановить композицию распределения: quota-card, заголовок, поиск/фильтры и таблица с мобильными подписями. Использовать действующий SolutionAllocation, не переносить Project allocation API.
4. Исправить scoped-стили и диалоги заявок: общие export/title/status/choice, DS-иконки вместо символа ×, вкладки решения/команды. Не менять payload, query и административные preview/apply.
5. Восстановить карточки и типографику аналитики, общие icon/graph/control components, состояния loading/error и вложенные таблицы. Не удалять coverage и остальные метрики V2.
6. Выполнить browser matrix для обеих версий, всех семи настроек и сертификатов на пяти ширинах; отдельно dialogs, filters, row actions, selection, focus и отсутствие доступа. Сохранить снимки до/после и результаты. Проверить локальные состояния с fixture; live/backend evidence указывать отдельно.
7. Запустить tests с ограниченным числом workers, проверку контракта, production build, локальные lint/format и requirement/code review. При общем компоненте приоритетна регрессия V1.

Новый дизайн не проектируется: визуальное восстановление V1 явно разрешено заданием. Новые DS additions не нужны. Особые риски: scoped CSS Angular в дочерних компонентах, мобильные `nth-child`, выбор скрытых фильтром строк, focus после закрытия диалогов, сохранение Solution ID и snapshot/preview tokens. Изменения server-side permissions и API не входят в план.

## Подтверждение результата

Реализация выполнена в отдельной ветке. Основные причины расхождений: повторная разметка экспертов, импорт стилей аналитики в экспертов и зависимость общих Angular-стилей от scoped-предка, которого нет в дочернем компоненте. Данные и обработчики V2 оставлены в его компонентах.

- Выделены общие [ExpertRosterComponent](../../projects/social_platform/src/app/ui/pages/program/management/experts/expert-roster.component.ts), [подписи состояний экспертов](../../projects/social_platform/src/app/ui/pages/program/management/experts/expert-presentation.ts) и [SCSS таблицы](../../projects/social_platform/src/styles/_program-expert-roster.scss). V1/V2 используют одинаковые аватары, профили, статусы, чекбоксы, меню, пагинацию и мобильные карточки.

### Обоснованные различия V1/V2

1. V1 управляет Project/ProgramProject, V2 — заявкой и самостоятельным Solution со снимком формы, составом команды и административной историей. Названия и доступные действия отражают эти сущности.
2. Таблица заявок V2 сохраняет действующий контракт восьми колонок. Презентация остается действием меню и загружается из полей решения по требованию; механическое добавление девятой Project-колонки потребовало бы загрузки каждого решения и предположения о назначении динамического поля. Чекбоксы, плотность, меню и статусы согласованы с V1.
3. Форма решения сохраняет templates, purpose полей, validation и snapshots. Это развитие бизнес-модели, использующее существующие field/editor/preview компоненты, а не новый стиль.
4. Распределение использует актуальные Solution preview/apply, quota, eligibility, own-team и protected-ограничения. Старые Project-счетчики roster не подменяют назначения решений.
5. Аналитика сохраняет дополнительные метрики покрытия полей и данные задержавшихся экспертов V2. Общая сводка оценивания не делает запросы к legacy Project API ради повторения старого подробного списка экспертов. Отсутствие таких запросов проверено браузерным assertion.
6. Удаление регистрации и участника в V2 сохраняет отдельный серверный прогноз последствий. Внешняя оболочка использует общие Modal/Alert/Choice.

### Ограничения приемки

**Стандартная production-сборка не проходит.** Обычный `npm run build:prod` упирается в запрет Cloud на скачивание Google Material Icons. При отключении только font inlining остаются пять превышений существующего лимита CSS 15 kB; тот же набор воспроизведен в отдельном worktree исходного commit. Размеры до → после: certificates 17,33 → 17,33 kB; management 24,91 → 25,00 kB; experts 24,65 → 24,83 kB; analytics 15,07 → 15,07 kB; drilldown 19,57 → 19,57 kB. Новых компонентов сверх лимита нет. `angular.json` и budgets не менялись. Диагностический production-артефакт успешно собран с оптимизациями, отключением скачивания шрифта и проверки budgets; это не успешный стандартный production build.

**Реальный API не проверен.** Нет настроенной сессии организатора и ID тестовых программ V1/V2. Браузерные проверки подтверждают клиентские сценарии с fixtures, включая PATCH настроек и preview-запросы. Они не доказывают сохранение на сервере, отправку писем, реальный PDF/Excel, транзакционные конфликты или серверную авторизацию. Для завершения приемки нужен прогон на тестовых программах с реальным API.

Figma использована через MCP, а не только через исходники. Полный context аналитики и один из context основного раздела не вернулись по таймауту: для основного раздела получен отдельный screenshot, для аналитики прочитана структура всех секций и сводка, а полный экран сопоставлен с действующей реализацией V1. Проверка не выдается за попиксельное сравнение каждого состояния с Figma. Связанные публичные/участнические маршруты решений, оценивания и запуска проверены по коду и существующим тестам; они не включены в 140 основных снимков управления.

Итоговая приемка остается открытой по стандартной сборке и реальному контуру. Merge, deploy, миграции и изменения данных действующих программ не выполнялись.
