# Вакансии проекта: активные и архивные

Дизайн согласован пользователем 21.10.2026 сообщением «по размерам UI KIT, 26–27 px … можно в дев».
[Figma](https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE/PROCOLLAB-Design-System-v1?node-id=776-5414).
Высота обеих вкладок — 27 px, без общей серой подложки; Mont в приложении.

## Исходное и целевое поведение

Angular dev cc95cda8: общий список вакансий, native confirm удаления, ошибка API не показывается.
API dev 1c424ff: PATCH is_active существует, но не завершает ожидающие отклики; DELETE не защищает историю.
В Figma зафиксированы два списка, перенос, возобновление набора и модалки с последствиями.
Архив соответствует is_active=false, отдельная сущность не нужна.
В API добавлен внутренний resume_on_publish для отличия архива от временного скрытия вместе с черновиком.
Создание и редактирование сохраняют существующую форму, навыки и серверные проверки.

## Роли и правила

Изменения доступны руководителю проекта и администрации; сервер повторно проверяет право под блокировкой.
Закрытие отклоняет только ожидающие отклики с email-уведомлением после commit. История сохраняется.
Возобновление допустимо только для опубликованного публичного проекта; прежние решения не меняются.
По ответу пользователя 21.10.2026 архивные вакансии остаются в архиве до ручного возврата,
в том числе при повторной публикации проекта. Новые вакансии черновика публикуются вместе с проектом.
Наличие любых откликов запрещает удаление, включая архивные вакансии.
Блокировки согласованы с откликами: Project → Vacancy → VacancyResponse.

## Контракт

PATCH /vacancies/{id}/ с is_active=false/true, DELETE /vacancies/{id}/ сохраняются.
Добавляется readonly total_response_count во все представления вакансии;
response_count сохраняет прежнюю семантику ожидающих откликов.
DELETE с историей: 400 с code=vacancy_has_responses и detail; чужой объект — прежний отказ permissions.
PATCH закрытия атомарен с завершением откликов. Запрос без is_active не меняет жизненный цикл.
Frontend использует существующий UpdateVacancyUseCase и не заменяет server-side checks.

## Acceptance criteria

- AC1: руководитель переключает активные/архивные; счетчики соответствуют данным проекта, вкладки высотой 27 px.
- AC2: после подтвержденного успешного закрытия карточка переходит в архив; до успеха список не меняется.
- AC3: возобновление возвращает карточку в активные; прежние решения сохраняются; непубличный/черновой проект получает объяснение отказа.
- AC4: удаление без откликов требует подтверждения и обновляет список только после успеха.
- AC5: с любыми откликами удаление запрещено и через прямой API; UI объясняет причину и предлагает архив для активной вакансии.
- AC6: ошибки оставляют модалку открытой, повтор доступен, двойная отправка блокируется. Ошибочный запрос не отклоняет отклики и не удаляет навыки.
- AC7: пустые списки, неизвестное число откликов, мобильный экран 320/390, keyboard tabs, modal Escape/trap/return focus не теряют контекст и данные формы.
- AC8: повторная публикация проекта сохраняет архив, дату закрытия и историю. Ручной возврат разрешен после публикации; новые вакансии черновика продолжают публиковаться вместе с проектом.

## План и границы

1. API: атомарный lifecycle, защита удаления, общий счетчик истории, regression tests.
2. Angular: состояния действий в фасаде, фильтрация и вкладки, существующие Card/Modal/Button/State, интеграция с use cases.
3. Проверки: API/Angular targeted tests, build, browser fixtures для desktop/mobile и ошибок, review от AC, связанные PR в dev.

Backend с миграцией vacancy.0011 должен попасть в dev первым. PR frontend зависит от backend.
Старые закрытые вакансии, в том числе в черновиках, остаются закрытыми: причина прежнего закрытия не сохранялась.
Миграция добавляет внутренний флаг с default=false и не меняет статусы/даты; нужные старые записи можно вернуть вручную.
Изменения React, production, глобального UI Kit и соседних страниц не входят в задачу.
Данные browser fixtures не подтверждают работу deployed API; это отдельное ограничение отчета.
