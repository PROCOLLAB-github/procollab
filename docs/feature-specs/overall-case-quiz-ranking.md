# Общий рейтинг кейс-чемпионата

## Решение и границы

12 ноября 2026 владелец выбрал простое сложение: кейс из 100 плюс квиз из 100,
общий максимум 200. Рейтинг доступен только организатору. Проценты критериев
остаются внутри кейса; долей этапов нет. Квиз и его экран пока не переносим:
дизайн квиза не согласован.

API spec и O01–O11:
`PROCOLLAB-github/api:docs/overall-case-quiz-ranking.md`, интеграционная ветка
`codex/white-label-foundation-20261110`, PR #861.

Сервер отдает готовые места, баллы, готовность и статусы. Отсутствующий этап
имеет `null`; настоящий ноль отображается как `0,00`. До завершения обоих
этапов общего итога и места нет. Равные суммы делят место: 1, 1, 3.
Поиск/фильтр не меняют глобальные места. Angular не пересчитывает кейс,
результат квиза, сумму или места и не записывает баллы вручную.

## Предлагаемый экран — ожидает подтверждения

В существующем разделе «Оценивание» добавить пункт «Общий рейтинг» после
«Результатов». Существующие результаты кейса сохраняются. Новый пункт только
для конкурсной программы с `solutionStorageMode === "legacy_project"`;
ProgramSolution не входит в этот контракт. Прямой API независимо проверяет права.

Pattern: расширение текущего ProgramManagement/Results. References:
`management.component.{ts,html,scss}` и `results/results.component.{ts,html,scss}`.
Figma: экран не создавался, потому что запись в Figma не запрашивалась.
Canonical DS reference:
<https://www.figma.com/design/tvog0fpEgWgEtr7KUTjbyE/PROCOLLAB-Design-System-v1>.
Часть текстовых DS contracts отсутствует в текущем checkout; визуальная
совместимость проверяется по реальным соседним компонентам, Mont и токенам.

Компоненты: существующие Icon, Button, Field/Choice, card/results layout;
доступная таблица со столбцами «Место», «Команда», «Кейс», «Кейс из 100»,
«Квиз из 100», «Итог из 200», «Статус». Поиск по команде, статус, обновление
и Excel. Новых DS primitives нет. Токены текущего экрана: `--accent-text`,
`--grey-for-text`, `--black`, `--medium-grey-for-outline`, `--light-white`.

Состояния: загрузка с `aria-busy`, пустая программа, нет совпадений,
ошибка с повтором, 403/404, ненастроенный кейс с переходом к критериям,
ожидание одного/обоих этапов, готовый настоящий ноль. Предварительный балл
кейса не должен выглядеть окончательным: статус показывает число полных
экспертных оценок. На узком контейнере строки перестраиваются в читаемые
блоки; видимый порядок совпадает с DOM. Длинное название переносится.
Кнопки имеют доступные названия, поля — labels, клавиатурный фокус виден.

Конкретные desktop 1440/mobile 390 макеты показаны владельцу 12 ноября.
Статическое preview прошло 9 Chromium checks: Mont, отсутствие page overflow,
поиск с сохранением места, настоящий ноль, длинное название, loading/empty/
error/unconfigured и keyboard. JS page errors: 0. Это проверка макета,
а не работающего Angular с новым API. Runtime UI еще не реализован.

Bounded Impeccable/continuity review: сохранены плотность Results и навигация
ProgramManagement. Исправлены три наблюдавшиеся проблемы: слишком сильный
акцент текстовых refresh/export действий заменен существующими иконками;
активный подпункт на мобильном прокручивается в видимую область; двойная
рамка фокуса поиска устранена без удаления focus state. Layout detector для
preview: 0 findings. Полный critique не запускался. Общая AA-сертификация
по макету не заявляется.

Task state: **DESIGN APPROVAL REQUIRED**. До явного подтверждения показанного
экрана Angular runtime не меняется. Backend, admin и XLSX независимы от этого
ожидания. Квиз требует своего отдельного согласованного дизайна.

## План реализации после подтверждения экрана

1. Новый domain `ProgramOverallResults`/row/status по API; не расширять union
   Project/ProgramSolution и не смешивать ID связи, проекта и программы.
2. Добавить GET и export в существующие port → repository → use-case → HTTP
   adapter, сохранив snake/camel mapping инфраструктуры и `ResultsQuery`.
3. Добавить organizer-only section/deep link в management и отдельный
   read-only компонент по согласованному экрану. Сохранять фильтры/query,
   отмену устаревших запросов, состояния и server-owned места.
4. Проверить adapter contract/null/zero/filters, component loading/error/
   pending/permissions, navigation и отмену запросов. Релевантные Vitest,
   scoped ESLint/Prettier, Angular build и реальные desktop/mobile browser
   checks с локальным API; затем review и обновление PR #540.

Порядок будущей установки: совместимый API и добавочная миграция → Angular.
На живом пилоте тестовые результаты не создаются; dev/prod не обновляются.
