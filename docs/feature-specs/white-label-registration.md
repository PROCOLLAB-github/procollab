# Короткая регистрация в клиентском экземпляре

Существующая `/program-registration/:id` получает дополнительный вариант из API.
При `account_mode: "email_password"` новый участник вводит почту, пароль/повтор и
подтверждает прежние согласия. ФИО и дата рождения скрыты и отсутствуют в payload;
обязательность динамических вопросов анкеты остается. Письмо и подтверждение
используют существующий flow, затем открывается программа без общего онбординга.

`branding: {name, logo_url}` задает имя и логотип формы, входа и заголовка вкладки.
Без логотипа показывается имя клиента. Компоненты, Mont, стили, состояния формы,
ошибки, ссылки, сохранение ответов, подтверждение почты и permissions сохраняются.
Новая страница и новый макет не создаются; квиз не входит в изменения.

Без новых ключей API форма сохраняет полные поля и бренд PROCOLLAB. Отдельно
TokenService сохраняет production cookies для текущего клиентского host;
домен `.procollab.ru` используется на доменах платформы, ключи dev/prod прежние.

## Критерии и проверка

- WL10: скрытые поля профиля отсутствуют в payload, остальные проверки работают.
  Component tests: короткая/полная форма, пароли, согласия, вопросы и переход назад.
- WL11: имя/логотип и заголовки зависят от API, обычная форма сохраняет бренд.
  Component и HTTP adapter tests проверяют в том числе вложенное snake/camel casing.
- WL12: клиентский host получает собственные production cookies, домены платформы
  сохраняют общий domain. TokenService tests включают похожие посторонние домены.

Проверки 10 ноября 2026: 44 целевых Vitest tests (component, HTTP adapter,
TokenService, AuthRequiredGuard и BearerTokenInterceptor), scoped ESLint/Prettier,
`test:solution-contract`, production Angular build. Полный Vitest suite не запускался.
Сборка проходит с предупреждениями Sass, budgets и CommonJS в существующих файлах.

В браузере Chromium production сборка работала с настоящим локальным API и
отдельной PostgreSQL. Проверены desktop 1440×1000 и mobile 390×844, регистрация →
локальное письмо → подтверждение → программа → reload с сохранением сессии.
Дополнительно проверены фокус с клавиатуры, отсутствие горизонтального скролла,
ошибка обязательных данных, переключение входа/восстановления. Консольных JS ошибок
в сценарии не было. Внешние запросы блокировались; адреса API перенаправлялись на
loopback перехватом браузера. Изображение логотипа проверено unit tests, реальные
клиентские assets еще не предоставлены. Детектор ошибочно пометил Angular `[src]`
как отсутствующий `src`; привязка и условие непустого URL подтверждены по source.

## Внедрение

Сначала backend с добавочным контрактом, затем этот frontend. White label на
общем стенде по умолчанию выключен. Схема БД не меняется. Реальные клиентские
домен/логотип, общий кабинет, favicon/статическая metadata, legal documents,
остальные письма и публичное развертывание входят в последующие этапы.
Адреса API/WebSocket клиентской сборки необходимо настроить отдельно: текущие
environment-файлы продолжают указывать на обычные dev/prod API. Этот PR не создает
и не публикует клиентский стенд. DNS/HTTPS/SMTP и нагрузочная проверка не выполнены.
